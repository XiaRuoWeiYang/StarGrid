# StarGrid 关卡与长期内容规划 / v3

## 总目标

Demo 制作 20 关；正式首发目标 50 关；产品底层按 200、500+
关持续扩展设计。关卡总数必须数据驱动，不设硬编码上限。

## 内容生产模型

长期关卡由"尺寸 × 星数配额 × 规则组合 × 区域结构 × 特殊条件 ×
教学阶段"形成组合空间。

每个新机制按： 教学 → 练习 → 组合 → 进阶 → Boss 进入游戏。

## Demo 1--20

  范围     尺寸方向     主要内容                  目标
  -------- ------------ ------------------------- -----------
  1        2×2（4格）   点击放星/取消、基础行列   教学
  2--3     3×3 → 4×4    行列规则                  基本习惯
  4--7     4×4 为主     引入不接触                空间约束
  8--12    4×4 → 5×5    区域、行列组合            区域推理
  13--16   5×5 → 6×6    完整基础规则              综合练习
  17--19   6×6          更复杂组合                进阶
  20       6×6          第一章 Boss               Demo 收尾

具体区域数据、解数量和难度在实现时由 solver 验证后写回本文档。

## 21--50

优先验证
2★/多星配额是否适合作为第一个大型变化。必须先原型和真人试玩，不因规划存在就强制上线。

后续可从固定星、禁止格、不同区域配额等低美术成本机制中选择已验证机制组合。首发
50 关应保留后续更新空间。

## 51--200

以章节方式逐步释放成熟机制，每 20--50
关一个大主题。优先复用成熟机制形成新组合，避免机制膨胀。

候选机制： - 2★/多星配额 - givens - blockedCells - 区域不同配额 -
部分区域规则 - 至少/至多 N 星 - 星座/图形附加目标 - 特殊区域关系

## 201--500+

不预先锁死具体规则顺序。采用章节包/内容包方式，每个包可包含旧规则新组合、新区域模板、新尺寸、新配额、一个经过验证的新机制、综合
Boss，以及每日挑战可复用规则池。

## 解与难度

不强制唯一解。胜利始终按启用规则验证。solutionType 可记录 multi /
limited / unique。

难度不能只看解数量。后续分析指标包括尺寸、配额、解数量、候选分支、强制步骤、推理链长度、区域复杂度、跨区域约束和特殊规则数量。

## 每日挑战

1.  热身：极简单小棋盘，快速完成。
2.  真正挑战：明显更难，使用已经正式教学过的成熟规则。

第二关不强制唯一解，但必须有解并通过验证。若随机生成不能稳定保证质量，应优先从预验证题库抽取。

## LevelData 长期契约

建议字段：
id、chapter、levelNumber、size、name、kind、rules、regions、starQuota、givens、blockedCells、difficulty、tutorial、solutionType、tags、version。

不得在 UI、存档、solver 或导航中假定只有 20/50/100/200/500 关。

## 质量门槛

每个正式关卡至少满足： - 数据合法。 - 至少一个合法解。 - RuleSystem
可验证全部启用规则。 - 多解不会被误判。 - 教学文案与规则一致。 -
通过自动验证。 - 关键章节关通过人工试玩。

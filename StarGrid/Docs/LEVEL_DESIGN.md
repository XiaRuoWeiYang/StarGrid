# 关卡与数据设计

## 当前关卡：garden-01 / 星光花园
6×6；六个正交连通区域；每区一星。布局如下，每个字母对应一种颜色：

```text
A A A A A B
A C B B B B
A C C C C C
C C C C C D
C C E E D D
C C E F F F
```

从较小的 E/F/D 区域与行列约束开始排除，结合两星不能斜接触逐步缩小范围。难度暂标为入门展示，尚未经过玩家推理步数标定，不能把解唯一等同于简单。

开发者答案（行列均从 1 开始）：(1,1)、(2,4)、(3,2)、(4,6)、(5,3)、(6,5)。网页线性索引为 [0,9,13,23,26,34]。

网页数据内嵌在 game.js，确保 file:// 直接启动，不依赖 fetch。正式版导入 JSON 或 ScriptableObject；校验尺寸、区域长度/范围、区域连通性、规则 ID 及答案合法性。solution 用于验证与提示，不是胜利判据。扩展字段建议包含 schemaVersion、chapter、difficulty、tutorialSteps、hintBudget。

## 唯一解验证与 solver 计划
本次用独立离线枚举检查全部 6! = 720 个列排列，排除相邻行星星斜接触后剩余 90 个，再检查区域约束，最终恰有 1 解。该检查只验证这个固定关卡，不代表通用 solver 已完成。

后续制作可复用 solver：读取 LevelData → 约束传播 → 最少候选格/区域优先搜索 → 发现第二解即提前停止 → 输出 0、1、≥2 解与示例。为教学难度另外记录单步排除、跨区域推理与回溯次数；超时状态必须单列，不能宣称唯一。生成器从合法解扩展连通区域，再交给 solver 筛选，最后由真人试玩。

## 第一章计划（未实现）
产品模式为逐步闯关，后续增加每日挑战。先验证 5 个难度递进样板关，不直接批量铺设 100 关。

| 首批范围 | 教学与难度目标 |
| --- | --- |
| 1–3 关 | 小棋盘、少量规则，学习点按与行列概念 |
| 4–8 关 | 引入正交/斜向接触、区域一星与 X 排除 |
| 9–15 关 | 完整 6×6 规则，逐步联合考虑多个条件 |
| 16–20 关 | 保持规则稳定，增加推理深度，作为阶段挑战 |

小棋盘教学必须匹配规则：例如 3×3 不应同时启用每行/列一星与八方向不接触，因为该组合无解。每个样板关都应独立验证。仅行列约束的教学关可以多解，必须接受所有合法完成方式。后续区域谜题需经过唯一解验证后发布。暂不添加墙、月亮或传送格，优先打磨基础玩法。

## 每日挑战计划（未实现）
普通关稳定后，每天提供一张统一且经过 solver 验证的困难棋盘。难度来自推理深度，允许分享完成与提示次数；不以极低通关率或强迫试错为目标。后续需定义日期时区、每日题目 ID、版本固定、完成记录及分享格式。当前没有排行榜、服务端或分享实现。
